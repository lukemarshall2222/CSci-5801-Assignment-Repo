The architectural pattern that best fits the important aspects of the LOAFR system is the repository architecture. The repository in this case is filled with labeled, unprocessed logs. In interactive use the data is held either in a remote repository or on the user's machine, and the machine does the processing. The appropriate logs are returned from a request and the user machine processes them according to the user query. When the user completes batch processing of some data, the architecture takes on a client-server feel because the processing is completed near the repository and the processed result is served back. A machine local to the repository is used to complete processing needed to answer a user query, and the result is returned, so that data transfers are kept small. The difference is in where the processing of the logs takes place.
